# 金山PDF 11.x 右键菜单消失修复补丁

> 修复 Windows 11 24H2 / 25H2 上「金山PDF」（11.8.0.8845 独立版，即"金山PDF专业版/教育版"）右键菜单消失的问题。
> 只需补一条机器级 COM 注册，**原版菜单（含拆分合并、格式转换等全部官方子菜单）即可完整恢复**。

## 问题现象

- Windows 11 24H2 / 25H2 上，安装金山PDF后右键任何 PDF / 图片文件，都没有「金山PDF」快捷菜单
- **重装金山PDF无效**（安装器永远把关键注册写在用户级）
- 同一台电脑的 Windows 10 分区、或未升级的 Win11 23H2 虚拟机上，菜单完全正常

## 根因

**Windows 11 24H2 起，资源管理器不再解析"用户级（HKCU）COM 类注册"**（安全加固方向），而金山PDF安装器恰好把右键扩展的 CLSID 只注册在用户级：

```
菜单处理器键（会被枚举到）：
  HKCU\Software\Classes\*\shellex\ContextMenuHandlers\kwpspdfshellext
      -> {8FE8AC65-EE7F-4C29-AF72-D2BACB633558}

CLSID 实际注册位置（新系统不再为外壳扩展解析这里）：
  HKCU\Software\Classes\CLSID\{8FE8AC65-...}\InprocServer32
      -> ...\office6\kwpspdfshellext64.dll
```

于是 Explorer 枚举到处理器键后，解析其 CLSID 时被无视 → 扩展从未被加载（进程模块列表中该 DLL 永远不出现）。

**修复 = 把同一个 CLSID 补注册一份到机器级 `HKLM\SOFTWARE\Classes\CLSID\`，原版菜单立即恢复。**

## 常见问题

**Q: 重装金山PDF后需要重新打补丁吗？**
A: 不需要。补丁写入的 HKLM CLSID 指向的是安装目录里的 DLL 文件路径，只要安装路径不变就一直有效。路径变了重跑一次安装补丁即可。

**Q: 卸载 8 月安全更新能解决吗？**
A: 不能。已实测回退 KB5121003（build 26200.9168 → .8973）后菜单依旧缺失，说明问题出在 24H2 分支更早的变更中。安全更新请正常安装。

**Q: 多选文件右键合并，只进一个文件？**
A: 这是 Win11 新版菜单对静态/传统扩展的通病（逐文件触发），与金山无关。多文件场景建议进「PDF合并」窗口后再添加文件。

**Q: 未来会自己好吗？**
A: 如果金山官方在新版本中改用机器级注册（或微软调整策略），原版菜单自然恢复，届时本补丁可直接卸载，两者不冲突。

## 进阶：恢复的菜单显示为英文内部名？

11.8 版扩展 DLL 默认显示内嵌英文 ID（如 `EditWithWPSPDFPro`、`pdfsplitmerge`）。
中文显示名来自扩展的资源体系：升级包 `kwpsshellextcfg` 内的
`shellext\menu_2.xml` + `shellext\mui\zh_CN\tr.xml` + 图标。

实测存在两条路线，可靠性不同：

### 方案A：部署资源树（轻量，但不是所有机器都生效）

1. 从一台装有新版金山PDF/WPS 的电脑取一个东西：
   该机器 `%APPDATA%\kingsoft\wpsufd\addons\pool\win-i386\kwpsshellextcfg_3.1.0.1`
   **这一个子目录**（99 个文件 / 134KB，含 menu_2.xml + zh_CN 翻译表 + 图标）
   —— 其余约 200MB 插件池内容与右键菜单显示无关，可全部省略
2. 先运行本仓库安装补丁（HKLM CLSID 修复必须就位）
3. 把该子目录按**原相对路径**放到本机
   `%APPDATA%\kingsoft\wpsufd\addons\pool\win-i386\` 下
4. 重启 explorer → 中文完整原版菜单

> ⚠️ **可靠性警告（2026-08-23 实测反例）**：一台 Win11 23H2 (22631) +
> 金山PDF 11.8.0.8845 的机器上，官方更新组件已**自动下载了同一份资源树**
> （menu_2.xml 与 mui\zh_CN\tr.xml 经 SHA256 比对与手工提取逐字节一致），
> 且 11.8 原版 DLL 未做任何改动，菜单却仍显示英文内部名；换装方案B的
> DLL 后立即恢复中文。说明"资源树能否被 11.8 DLL 读取"还存在未定位的
> 机器相关条件，本方案不保证在所有机器上生效。若无效，请直接用方案B。

### 方案B：换装 12.x 扩展 DLL（实测确定性生效）

用新版 WPS/金山PDF 的 `kwpspdfshellext64.dll`（如 12.6.0.22857，自带内嵌
zh_CN 字符串）覆盖安装目录 `office6\` 下的同名文件并重启 explorer 即可；
即使删光 `%APPDATA%` 资源树也照样显示中文。重装金山PDF后重跑一次即可恢复。

仓库提供免参数脚本 **`一键升级中文菜单.cmd`**（调用 `升级中文菜单.ps1`）：

- 优先读 HKLM CLSID 定位安装目录，失败再按卸载表/目录扫描兜底
- 复制前结束已知宿主（explorer / wps / wpspdf）；每轮复制前做模块级扫描，
  找出真正占用 DLL 的进程（dllhost、SearchHost、第三方文件管理器等）并结束
- 写入后做 SHA256 校验；仍被占用则走"改名腾位法"兜底（Windows 允许重命名
  被占用的 DLL，腾出目标名写入新文件，失败自动还原）
- 全程出错保留窗口显示原因，不闪退

使用前请自备 `中文升级源文件\kwpspdfshellext64.dll`（及可选的 wpsufd 资源树）
放在脚本同目录。注意编码：`升级中文菜单.ps1` 必须带 UTF-8 BOM、`.cmd` 为
GBK+CRLF——否则 Windows PowerShell 5.1 / cmd 会把中文路径解析成乱码直接失败
（GitHub 网页对 `.cmd` 的预览可能乱码，下载到本地运行不受影响）。
